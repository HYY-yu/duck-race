# 玩法与工程设计

更新日期：2026-10-22；模拟版本：`sim-0.5.0`。

## 产品定义与视觉

观赏型自动水道竞速：每个名字对应一只鸭，观众通过跟随镜头观察水流、路线与障碍怎样改变名次。当前固定 5 位选手，先完善一条复杂且可读的立体水道。首先保留中英文，不擅自扩展其他语言；本轮不做声音。

「叠瀑山谷 / Cascade Highlands」采用连续山脊、暖灰岩壁、绿色坡地与林带，配青绿色水面和少量橙色障碍。赛道占据主要画面；侧栏保留选手、比赛控制与当前河段信息。初始全景用于交代整体布局，开始时切入 3D 俯视跟随。起跑灯、流动水纹、障碍动作和镜头过渡承担玩法说明作用。两处分流岛有真实实体边界和不同支流水位；三段大落差连接缓冲池。

搜索定位仍可承接 duck race / name picker，但水道与障碍本身不证明市场差异或需求。相关事实与假设保留在 [调研索引](research/README.md)，不把本次工程完成等同于商业验证。

## 地图与共享水流

水道中心线水平长度约 358.54 个场景单位，整体水面从高度 70 降到约 6.79，按界面米制尺度显示约 359 m 全长与 63 m 落差。起跑线位于 `s=4`，终点线位于 `s≈348.54`，之后保留 10 m 缓冲池。`s` 是水平中心线距离，不是鸭子所在分支的精确三维弧长。

第一处从 s=34 的崖口自由下落，标称水帘在 s=39.5 入池；河床在 s=34–35.1 下降 9 m，水潭深度增加 1.35 m。后两段集中落差位于 176–196、282–302 m，分别额外下降 11、12 m，叠加整个河道持续的缓降；两处分流各额外下降 7 m。左右支流端点相同、下降时机不同，最大水位差约 2.7 m，沿程均保持向下。

普通河段宽约 10.8 m、深约 1.04 m；深窄道最窄宽约 2.6 m、深约 1.74 m。对应过水截面从约 11.23 m² 缩小到约 4.52 m²。流速由统一流量除以截面积、再结合坡降修正；窄道代表中心流速约 10.89 m/s。加深没有抵消收窄带来的截面积减小，不能推广成「深水必然更快」。

分流把统一流量分给两条真实支路，分水比例随共同的时间相位变化。岛体偏置、支流宽深和下降时机让路线优势变化；汇流后恢复主河道。鸭子在入口按实际横向位置进入支路，经过岛体期间不会穿岛换线，出口恢复主河道约束。所有鸭子采样同一位置和时间的流场，名字、身份和排名不参与计算。

`channelSpans`、`sampleChannel` 与 `sampleSurface` 为运动、水面、河床、两侧岸壁、岛体及镜头提供共同几何。水面按 `RIVER_REACHES` 分段建立，分流段没有横跨实体岛的假水面。地形包含连续山谷、裸岩脊、碎石坡和实例化植被。

## 水体、反射与河床

水体复用 Three.js r180 Water2 的双相流动法线核心，采用错开 2 秒的 4 秒周期交叉混合，使相位在权重为零时重置，限制空间变速造成的累计 UV 剪切。两张 256 × 256 可平铺法线由项目原创程序生成，使用 `DataTexture`、mipmap 与线性过滤，没有外部图片请求。法线沿各支流的横向与下坡方向，在视图空间中扰动实际几何法线；不同高度和坡向的河段不会共用水平水面的法线假设。来源、取舍见 [开源调研](research/water-rendering-open-source.md)，改编代码保留 [MIT 版权与许可](../public/licenses/three-water-MIT.txt)。

表面使用 `MeshPhysicalMaterial` 的透射、折射与吸收：折射率为 1.333，局部厚度按支流深度和距岸距离变化，呈现岸边较浅、中央较深的颜色与透射。这里的厚度是材质近似，不是实时求得的水体体积或逐像素真实水深。白水根据坡度、落水区和岸界增强，同时提高粗糙度、降低透射；细节使用屏幕导数过滤，减少远处亚像素噪声。顶点有厘米级起伏并在岸边衰减，只影响渲染，不改变碰撞、水位采样或鸭子动力。

反射环境在初始化时从实际山谷场景和 Three.js 程序 `Sky` 一次性生成，使用 256 分辨率 PMREM。探针位于河道中段，供所有水面共享；它提供山体与天空的静态反光，没有局部视差，也不包含动态鸭子倒影。这不是 SSR，也没有为整条下降河网套用 Water2 的单平面 Reflector/Refractor。环境生成失败会传播到场景初始化的错误展示路径。

独立河床细节按每条真实支流铺设沙底，使用实例化碎石并保留较空的水底区域；碎石仅作装饰，不新增物理障碍。焦散是随时间变化、受水深衰减的程序亮斑，不是光线追踪求解。水面另外包含软边泡沫、叠瀑落水喷溅、入池浮沫及逐渐消散的鸭尾迹。粒子位置使用预采样水道缓存，分批刷新流速；泡沫、喷溅和尾迹使用实例化绘制。暂停冻结动态效果，重置清除旧比赛尾迹。

透射使用 Three.js 内部共享的不透明场景颜色缓冲，分辨率比例为 0.5。渲染目标有深度附件，但水体着色器没有读取屏幕深度来拒绝前景采样；材质厚度与吸收依据预计算的河道数据，因此折射在前景交界、画面边缘和离屏内容上仍有局限。透射增加了逐帧渲染开销，静态环境采集则只在初始化执行。`renderer.info.autoReset` 关闭，每帧主渲染前显式重置统计，因此 draw calls 和三角面计数包含阴影、透射与主画面，不能与只统计主画面的旧数字直接比较。环境生成另外记录采集时长和分辨率。

销毁时释放水面/河床几何、物理材质、原创法线与泡沫纹理、实例化对象和保留的 PMREM 输出；环境生成的临时资源在 `finally` 中清理并恢复渲染状态。场景拥有的 renderer 在销毁后释放 WebGL 上下文，清除其内部透射缓冲区。水体与河床的重复销毁有保护。新增 three.quarks 0.17.1 / quarks.core 驱动瀑布粒子，代码许可随 public/licenses/ 分发；Three.js / 类型分别固定为 0.186.1 / 0.186.0。

## 第一处自由水帘与接缝约定

`riverStations` 为水面、河床、河岸和岸外地形提供全局 0.35 m 采样站点，强制包含分合流端点、崖口、岩壁底部和入池位置。主河面 18 列、支流各 9 列使连接边顶点一一对应；水面法线由共享坡度解析生成，支流端点使用主河道坡度。`bankDistanceAt` 在岛尖尚未形成时忽略虚拟内岸，着色器波浪与 CPU 浮力探针共用；透射厚度也读取同一距岸数据。河岸外沿与地形肩部读取 `bankShoulder`，消除不同偏移和采样率产生的纵向裂线；岸外肩部按主地形实际三角形插值高度、颜色与法线，避免外沿明暗断层。分流入口/出口的流速在 5 m 内过渡到共享主流；第二处分流的固定入口偏置调整为 .65，补偿新落水轨迹带来的到达时相变化，参数不读取名次或身份。

第一处水帘为独立曲面，具有边缘厚度、双尺度流动纹理、随时间轻微摆动和逐渐增强的白水。崖后岩壁与水帘之间留有空隙，下方深潭有泡沫层。飞溅与水雾使用 three.quarks 的批量 billboard / stretched billboard，入水水花按鸭子复用五个发射器。水帘、粒子属于视觉近似，不是 MLS-MPM 或 Navier–Stokes 流体模拟。

鸭子跨过崖口后保存绝对高度和竖直速度；以 120 Hz、9.81 m/s² 重力积分，离水期间停用水阻力和水流旋转驱动，保留横向/前向惯性。入水按实际位置的水位相交判断，不固定落点、不按水帘进度传送。`takeoff` / `splash` 各发一次 Info 日志，不含姓名。入水速度控制短暂浸没/回浮和水花，随后恢复普通浮力。鸭间接触同时检查竖直间距，避免空中鸭子隔空推挤水中鸭子。暂停冻结模拟与 VFX，重置清理历史入水状态。

## 运动与碰撞规则

- 固定 5 鸭，起跑时速度为零，横向间距 1.7 m。种子仅打乱名字／身份对应的起跑槽位，不生成新地图、不改变障碍相位，也不持续加入个体随机速度。
- 鸭子是被动漂浮物，速度通过阻尼接近所处位置的水流。静水不会凭空推动静止鸭子；没有鸭子自身的推进速度、排名补速或预设赢家。
- 运动使用沿河距离与横向偏移表达，弯道曲率修正内外侧线路的推进距离。所有鸭使用统一半径 0.62 m，与外观和名字无关。
- 两个摆锤位于 `s=140/160`，球半径 0.9 m、摆臂长 4.5 m。碰撞使用渲染相同的横向位置和高度，并考虑摆锤横向速度；摆到足够高时可以从下方通过。
- 三道横杆位于 `s=311/322/333`，半径 0.24 m，杆心高度在水面上约 0.22–2.52 m 之间变化。碰撞依据实际高度判断是否阻挡，不使用与画面脱节的开关状态。
- 鸭子间有 2.4 m 范围的对称短程斥力，随距离平方衰减，单步冲量不超过 0.06；隔岛不生效。它缓解可见拥挤，不依赖身份或名次，也不参与远距离追赶。接触后采用等质量分离与法线冲量。每步执行 8 次约束迭代，交替处理鸭间接触、岸界和障碍，避免窄道队列互穿或挤过闭合横杆。
- 过线时间在固定步长内按前后位置插值记录。已完赛鸭仍随水流进入缓冲池，比赛在全部完赛时停止；不会传送到领奖位置。
- 已完赛者按完成时间排序，未完赛者按沿河进度排序，完全相同则按固定身份编号稳定展示。该规则不等同于终点摄影或公平抽签机制。

## 被动朝向与浮力姿态

鸭子保存独立的世界朝向 `heading` 和角速度 `angularVelocity`。渲染不再把朝向覆盖成速度方向或河道切线。共享水流通过局部世界速度场的半旋度施加角速度阻尼；侧岸、鸭间和障碍接触按小型非对称压力力臂传递旋转冲量，角速度有界。没有目标朝向、自动回正、主动划水或朝向驱动的推进；横漂和倒漂是正常结果。该旋转近似不改变现有圆形平移碰撞器，因此朝向不同不会产生新的速度优势。

鸭身以身体中心为旋转支点，身体中心在水面上约 0.28 m、身体竖向半径约 0.45 m，静态约有 0.17 m 的下部入水。船首/船尾与左右共四个采样点读取实际支流水位及与 GPU 共用的波浪函数，驱动带阻尼的升沉、俯仰和横摇。波浪函数由同一参数表生成 CPU 采样和 GLSL，避免浮动与水面相位脱节。升沉相对局部水位计算并限制幅度，陡降时不会因为绝对高度弹簧滞后而悬在空中。

朝向按比赛固定步进积分；浮力姿态按渲染增量作有界小步积分。暂停冻结浮力，重置清理姿态缓存；待发令及完赛后仍可随水面轻微浮动。四探针与有界弹簧属于游戏浮力近似，未实现真实排水体积、翻覆或六自由度刚体。

## 比赛与镜头交互

状态依次为 `ready → countdown → running → done`，倒计时或运行状态均可进入 `paused` 并返回原状态。3 秒倒计时配合五盏起跑灯；倒计时期间所有鸭子保持原位，比赛计时从实际放行开始。

重置保留种子并清除计时、碰撞与完赛记录。完赛后可直接再赛一场。名单和种子仅在待发令状态可编辑。页面进入后台时自动暂停，不会在后台补跑数分钟；返回页面后由用户继续。180 秒未全员完赛会可见暂停并要求重置，不提供隐形传送救援。

跟随目标可通过排行榜、点击 3D 鸭子、数字键 `1`–`5`、左右方向键及镜头栏箭头选择。输入名字或种子时不拦截这些键。全景／跟随按钮可随时切换；小地图绘制左右支路并显示实际横向位置。相机在分流前预先扩大视野，覆盖左右水路，出汇口后逐渐回近；陡降段兼顾上游入口和下游缓冲池。短暂的分流、汇流和超越提示仅观察比赛，不反向影响物理。中英文切换保留自定义名字，默认名字跟随界面语言。

## 模块结构

| 文件 | 责任 |
| --- | --- |
| `src/course.ts` | 平滑中心线、连续水面高度、宽深、河段、共享流场、障碍及姿态 |
| `src/simulation.ts` | 被动漂流、角状态积分、岸界／鸭间／障碍碰撞、过线事件、排名 |

| `src/race.ts` | 3 秒倒计时、固定 1/120 秒步进、暂停恢复、重置、完赛及超时 |
| `src/scene.ts` | Three.js 场景组装、岸壁/鸭模型、障碍同步、相机/拾取、透射分辨率、全帧统计及资源释放 |
| `src/water.ts` | 实际支流水面、局部深度/坡向属性、白水/喷溅/尾迹、预采样流场缓存 |
| `src/water-material.ts` | 原创法线纹理、Water2 双相流动核心、物理透射吸收、局部法线与视觉起伏 |
| `src/water-environment.ts` | 一次性山谷与 Sky 环境采集、256 PMREM、渲染状态恢复与探针资源释放 |
| `src/riverbed.ts` | 分支沙底、装饰碎石、程序焦散及资源释放 |
| `src/terrain.ts` | 连续山谷、岩脊、岛体、林带/碎石实例与外轮廓 |
| `src/race-insights.ts` | 观察名次变化，过滤起跑和短时间抖动，不修改模拟 |
| `src/main.ts` | 控件、排行榜、双语、小地图、赛事日志、后台暂停和错误展示 |
| `src/style.css` | 工作区布局、响应式排版、状态和交互样式 |

渲染帧率与模拟步进分离，单帧累计时间上限 0.1 秒。纯模拟拒绝非有限时间或不合法步长。程序几何和现有 Three.js 即可完成本轮重构，无新增大型依赖。

这仍是带高度的水道坐标运动与共享流场近似，并非完整自由表面流体、真实湍流或六自由度刚体求解。鸭子跟随水面高度，不模拟翻覆、潜水或自由飞行。物理水材质用于表现光照、折射和吸收；水纹、起伏、白水和焦散均为视觉近似，不是水力或体积流体求解结果。

## 可观测性

赛事日志统一包含 `race_id`、`version`、`seed` 和模拟时间，不记录真实姓名。初始化水体环境另记录方法、分辨率及采集时长。错误同时进入日志和可见界面；WebGL 上下文丢失或渲染错误会停止动画并提示刷新。

| 级别 | 事件 |
| --- | --- |
| Info | `water_environment_ready`、`scene_ready`、`race_countdown`、`race_start`、`race_pause`、`race_resume`、`race_reset`、`race_complete`、`race_background_pause`、`duck_finish`、`river_split`、`river_merge` |
| Debug，仅 `?debug` | `camera_follow`、`camera_mode`、限频 `obstacle_contact`、`frame_sample`、`position_change` |
| Warn | `invalid_seed`（使用可见种子回退值）、`race_timeout` |
| Error | `scene_initialization_failed`、`scene_render_failed`、`webgl_context_lost` |

碰撞事件在每一步内按鸭子和障碍去重；累计接触数是接触采样数，不代表独立撞击次数。`frame_sample` 包含本地粗略 FPS、draw calls、三角面、几何与纹理数，不能替代正式性能分析；Debug 帧采样还包含各鸭朝向角度与角速度，用于检查被动旋转。`position_change` 对同一对选手设 2 秒提示冷却；界面计数属于名次变化观察值，不是独立的轨迹相交判定。

## 公平性与验收边界

相同水流与碰撞参数不保证相同胜率；起跑位置、内外侧路径和障碍相位可能产生偏差。交换名字只改变身份分配。20 个种子、100 只鸭完成比赛只说明有限样本内可完成，不能证明抽签公平、不同地形泛化或跨浏览器逐帧一致。

当前自动测试 54/54 通过，覆盖固定步进、被动漂流、几何连续下降、加速截面、两类障碍、支流水位连续下降、分流汇流、岛界/岸界、斥力对称有界、隔岛不相互作用、开阔支路间距、完赛和生命周期，并增加水体/河床几何、法线材质和资源释放约定。自动测试不等于 GPU 着色效果或实机性能验收；桌面浏览器检查与构建结果分别记录于 [开发计划与验收](PLAN.md)。低端 Android、iPhone、移动触摸与持续帧时间尚未实机验收。`reduced-motion` 关闭界面过渡，核心比赛动画仍可由用户暂停。
