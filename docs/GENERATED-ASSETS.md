## 离线处理

`node scripts/prepare-generated-assets.mjs` 自动选用存在的 `-v2` 原件，输出 `public/models/`，不触发付费生成。

- 用现有 meshoptimizer 做带 UV 约束的减面；细薄结构或接缝过多时保留完整网格，避免强行达到目标面数。实际约 1,800–10,000 三角面，具体见 `web-manifest.json`。
- 对位置重合的 UV 分裂点计算一致法线，但不焊接 UV。大多数资产只修法线；鸭子保留已批准的 Taubin 平滑版，围巾轻度平滑。
- 零面积/相消邻域用来源法线或有限方向回退，记录 Warn 和 manifest，不静默输出零法线。
- 本批彩色贴图缩至 512px，移除金属/粗糙度贴图，改为非金属哑光材质；围巾移除不用的纹理。鸭子沿用原先 1024px 配色纹理。
- 不引入新依赖，保留所有原始模型。体积、面数、来源版本见 `assets/generated/remaining-v1/web-manifest.json`。

## 运行时

`src/generated-assets.ts` 使用 GLTFLoader 加载显式模型子集、复用进行中的请求并缓存几何和纹理；鸭子按 `COLORS` 在本机生成共享身体配色，保留嘴和眼睛。挂件按编号循环：无、海盗帽、骑士头盔、眼镜、围巾。饰品不参与物理或随机分配。

`World.replaceGeneratedModels()` 按下面的阶段逐个原位替换视觉对象。期间保留原模型；下载失败记录 Warn 与 `asset_failed` 并保留对应 fallback；场景装配异常记录 Error。`window.__DUCK_RUSH__.generatedAssets` 提供 ready、coreReady、stage、requested、loaded、failed、attachmentFailed、milliseconds 与各模型 modelMs。

### 渐进加载（2026-10-23）

`src/asset-loading.ts` 在首帧之后立即请求鸭子，然后按阶段补全场景，每批至多两个模型，在非关键请求及装配前让出主线程：

1. `core`：duck，397,184 字节（约 388 KiB），完成即替换鸭子。
2. `trees`：仅当前场景中存在的树种；各树种独立替换自己的临时树，另一种加载失败时仍保留对应临时树。
3. `cosmetics`：海盗帽、骑士头盔、眼镜；仅刷新佩戴该挂件的鸭子。红领巾继续使用共享代码几何，不下载 scarf.glb。
4. `wildlife`：仅当前场景需要的飞鸟、兔子与桥上观众；观众逐个装配，保持现有动画及暂停逻辑。

当前松风山谷、雪岭激流两条赛道共享这些 GLB，赛道、水流和机关是程序化几何。`track.ts` 仅生成当前 URL 选中的一份赛道，`World` 仅构造这份场景；切换赛道走页面导航，未选中的赛道不会额外请求一套模型或构造一套场景。当前仍共享赛道生成代码的 JS 包；这里的按需加载指场景与模型请求，不代表各赛道代码完全分包。渐进加载以模型文件为单位，每个 GLB 仍需完整下载后才能解码。

默认完整场景从 13 个请求 / 7,525,460 字节降至 12 个 / 7,104,884 字节（约 6.78 MiB）。关键阶段 GLB 字节量减少约 94.7%，但这不是首屏总下载量或实际加载时间减少比例：Three.js、主程序、水面初始化和地形构建仍需完成。限流可能延长整套装饰全部出现的时间，目标是更早看到高精鸭子，并分散下载、解码与装配的峰值。

新增阶段日志与 `asset_stage_finished` 埋点，包含请求数、失败数和阶段耗时；不包含参与者姓名。失败不阻塞后续模型；再次显式请求失败模型可重试，已成功模型直接复用。单元测试覆盖优先顺序、并发限制、请求去重、按场景筛选及失败后继续/重试。

本次验证：85 项测试、生产构建和 `git diff --check` 通过；浏览器检查中英文、三条赛道、开始与跟随视角，正常场景请求 12 个 GLB、无失败。阻断 bird.glb 时进入 `degraded`，其他 11 个模型完成，简化飞鸟保留且仍可开始抽签；检查后已恢复网络设置。限速 250,000 B/s、延迟 100 ms、禁用缓存的标准赛道运行中，从 GLB 阶段开始计鸭子约 1.7 秒完成，全场景约 29.5 秒完成；这是本机开发环境的单次阶段时序，不是优化前后首屏速度基准。截图：`docs/screenshots/progressive-loading-follow.png`。构建仍有 Three.js 包大于 500 kB 和未配置 SITE_URL 的提示。

两种树各一个 InstancedMesh；兔子、鸭子共享几何。飞鸟加入翼骨；观众按位置生成头/双臂蒙皮权重，复用原有注视、拍手、挥手、跳跃及暂停逻辑。这是轻量自动蒙皮，不是手工完整角色动画。遮挡检测沿用保守场景代理。

### 树木摆布修整

`src/tree-layout.ts` 对原有随机散点进行确定性筛选，不额外消耗场景随机数。按实际 GLB 的横向包围半径留间距：阔叶树 3.2、松树 2.2（再乘各自缩放），树冠之间至少留 0.65 间隔。河道、机关、起终点、泉眼、观众桥及兔子活动点留净空；陡坡、树根高度变化过大或坡面进入树冠的位置拒绝种植。树根按周围采样最低地面略微埋入，减少斜坡悬空。

生成树与临时几何树使用同一份筛选结果，镜头代理同步采用各树种的实际尺寸，避免删掉树后仍遗留原位置的树冠代理。保留正常山坡与随机疏密，未改竞赛物理。新增测试覆盖实际模型尺寸、树冠间距、场景净空、坡面与确定性。

### 胸前红领巾（2026-10-22）

`src/duck-scarf.ts` 用共享几何构造哑光红围领、胸前居中的短结及两片下垂布角，替代不完整的生成围巾装配；无新增依赖、付费调用或竞赛物理变化。按用户要求改为胸前红领巾样式，移除向侧后方外展的飘带；两片布角保持在胸前中线，避开左右翅膀。领结下移至胸口并向内收，与鸭嘴留出间隙；布角根据现有鸭子胸部采样轮廓弯曲，细分后再变形，避免大三角面切入圆润鸭胸。编号循环保持不变，围巾不再依赖原始 scarf GLB 加载成功。

装配验收页新增「围巾多视角 / Scarf views」，同时展示正面、侧面与背面。截图：`docs/screenshots/duck-neckerchief.png`。此前全量 53 项测试通过；此次构建与围巾专项 2 项测试通过，检查胸前布角范围、有限几何、共享资源和无原始围巾模型时的装配。已进行浏览器多视角静态检查，尚未作真实手机比赛视角验收。
