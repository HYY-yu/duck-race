# 抽签流程 / Random name picker

Duck Rush 定位为可视化抽签工具：输入名单 → 锁定并开始 → 按实际冲线顺序展示完整排名。保留现有岛屿、障碍、跟随镜头与完赛入湖展示。

## 操作界面 / Workspace

左侧按使用顺序集中名单、开始/暂停/结果、重新开始；运行时显示计时、进度与状态。名单区域独立滚动，抽签记录与说明固定在侧栏底部。空名单时主按钮进入设置，配置后切换为开始抽签。

场景右上角保留全局/跟随镜头与当前赛道选择器，标签按实际配置显示“松风山谷”或“雪岭激流”。底部 Dock、天气温度、宣传语、机关说明与山顶/瀑布/湖泊路径文案已经移除。标题突出“随机抽签”，中英文使用同一操作结构。

每只鸭子头顶显示名字气泡及身体颜色圆点，使用相机投影跟随位置，始终保持屏幕文字方向。保存名单、开始后的姓名洗牌、重开与语言切换同步更新；屏幕外的气泡隐藏，邻近标签向上错开，过长名字省略，侧栏保留完整姓名。名字使用 textContent 写入，气泡不接收指针输入，不干扰镜头控制；复用最多 12 个 DOM 标签，不增加 WebGL 绘制或依赖。

顶部菜单仅保留「松风山谷 / Pinewood Valley」与「雪岭激流 / Snowpeak Rapids」，在当前标签页切换；切换会重新加载，保留语言与种子参数。标准赛道已下线，旧链接转到松风山谷；旧成绩仍标注「标准赛道（已下线）」，不改写其赛道。参见 [松风山谷说明](LONG-COURSE.md)。

点击「开始抽签 / Start draw」成功创建本轮后，默认开启声音并跟随第一只鸭子。页面打开时保持静音，音频初始化在开始操作的用户手势内触发；浏览器不支持或拒绝音频时记录 Warn，抽签继续。重复开始使用幂等开启，不会把已开启的声音切成关闭；比赛中仍可手动静音和切回全局。暂停/继续不重新覆盖用户选择。

2026-10-23 验证：87 项测试、生产构建和 `git diff --check` 通过。浏览器检查中英文双赛道菜单、旧标准链接及种子保留；两条赛道点击开始后均为声音开启（AudioContext running）和跟随视角，手动静音/全局与新一轮恢复默认均正常。截图：`docs/screenshots/draw-start-defaults.png`。

## 输入约定

- 每行一个名字，2–12 位参与者；忽略空行，去除首尾空白，使用 NFC 存储显示名称。
- 名字最多 40 个 Unicode 码点；禁止控制字符及不可见格式字符。
- 重名比较使用 NFKC 和小写转换，防止大小写、全半角、组合字符造成明显重复。重名请加编号；不静默去重或截断名单。
- 不设置中签人数，所有参与者按实际冲线顺序排名。开始后直至本轮结束/主动重置，名单锁定。暂停、镜头切换和语言切换不会重抽。
- 名单有效后，每位参与者可选 12 种鸭子身体颜色，默认“随机”。颜色按规范化后的名字关联，换行顺序调整不会丢失选择，新名字默认随机；可重复选择同一种颜色。
- 固定颜色随名字一起分配给物理鸭子编号。随机项在每轮开始时确定，优先从未被固定颜色占用的色板里不重复分配。颜色只是外观，不参与物理或冲线计算。配置预览中随机项使用占位配色，开始后显示本轮实际颜色；侧栏、提示、结果及场景同步。
- “同名单再抽”保留所有参与者，包括以前的中签者；下一轮开始才生成新的分配与种子。
- 名字显示在 HTML、属性、结果与记录中时统一转义；剪贴板输出原始纯文本。

## 随机与公平性边界

`src/draw.ts` 使用 `crypto.getRandomValues`，通过拒绝采样得到无取模偏差的有界整数，执行 Fisher–Yates 名单洗牌。仿真种子与记录 ID 另外取随机字，独立于姓名分配。安全随机源不可用时明确报错，不回退到 `Math.random`。

每位参与者随机获得一个物理鸭子编号，姓名不进入仿真。鸭子仍由水流与接触决定实际名次；不预设冲线结果，不隐藏加速，不为了公平而篡改物理过程。

物理编号受起点、碰撞处理顺序与赛道影响，不能据此宣称编号之间胜率相同。公平性的依据是**身份到编号的独立均匀分配**：对于任意固定冲线顺序，均匀姓名排列会产生均匀姓名排名，每人入选前 K 名的概率为 K/N（假设浏览器安全随机源正常，名单不在途中更改，且全部完赛）。测试验证三人排列的六种组合各出现一次以及种子/选取数量不改变身份分配的算法关系；这不等于对所有真实浏览器熵源进行统计认证。

这是本机运行的休闲抽签工具。ID、时间、种子和结果可用于本机留存；种子独自不能重建姓名分配。完整记录包含姓名映射，但没有签名、服务端承诺、第三方审计或防篡改证明。用户可以改代码、重开页面或重复抽取；记录不能证明只抽过一次。不宣称获任何独立认证。

## 数据与可观测性

- 名单仅在当前页面内存中处理，未完成的草稿不持久化。刷新页面会清空当前配置；已完成结果可从本机记录查看。
- 完赛后写入既有 `duck-rush-history` localStorage 键，最多 10 轮；新增 `names`（按鸭子编号）、`mode: ranking`、`drawId`；新记录不保存中签人数，旧记录的 `winnerCount` 继续读取。兼容旧版仅含时间/种子/鸭子编号的记录，旧记录始终使用原始内置名称，不借用新名单。
- 新结果同时保存可选 `colors`（按物理鸭子编号），读取时限制为色板中的合法值及正确人数；兼容无颜色字段的旧记录。颜色随机数在身份洗牌、物理种子和 ID 生成之后抽取，不改变这些分配。
- 不提供名单上传接口，不发送名字到日志或分析服务。本地记录会保留姓名；输入表单说明这一点，历史弹窗提供清除入口。
- 读取记录时校验日期、种子、完整且唯一的编号、顺序时间与名单配置。忽略无效记录并打印 Warn；存储失败打印 Warn 并在结果页提示复制留存，复制失败提供可选中的纯文本框。
- Info：名单配置的数量、抽签开始 ID/人数/排名模式、抽签完成。Error：安全随机初始化失败。预留事件位置供后续接入指标，不记录真实姓名。

## English

Enter 2–12 distinct names, one per line, and start. Entries are locked for the round. Browser cryptographic randomness independently assigns names to physical duck IDs; results show the full finishing order. Starting another round includes everyone again. Names and the last 10 completed results stay on this device. Refresh clears unfinished setup. Copy results before closing if local storage fails. This local tool has no independent audit or tamper-proof certificate.

当前模式仅展示完整排名，复制结果也不标记中签者；旧历史仍保留当时的中签标记。Legacy selection-count records remain readable; new draws return full rankings.


## 2026-10-26 重新开始与刷新状态

确认“重新开始”后，清空本轮计时、进度、结果、抽签会话和事件反馈，鸭子回到起点；保留当前参与者名单及颜色设置。镜头立即恢复全局并选中编号 0，避免跟随镜头从水车慢慢穿山返回起点，看起来像没有重置。取消确认只关闭弹窗，保留原比赛状态和进度。

普通刷新始终从待开始状态进入，不从历史记录恢复暂停中的比赛。开发检查 `?inspect=wheel` 等是一次性入口：加载时移除 URL 中的 `inspect`，但保留语言、赛道、地图种子、推广参数和锚点。当前检查可继续观看；重新开始会退出检查状态，之后正常完成的新抽签仍可保存历史。重新显式访问检查 URL 才会再次进入检查点。
